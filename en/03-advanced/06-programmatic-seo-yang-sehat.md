# 06. Healthy Programmatic SEO

**Level:** Advanced | **Reading time:** 15 minutes | **Prerequisite:** 03-advanced/05

## Goal
Build template- and data-based pages without falling into scaled content abuse.

## When programmatic SEO makes sense
When there is real data that differs for each page and that data is useful to users. Examples: a directory with unique data per entry, calculators, comparison pages with real attributes.

## Feasibility test before building
1. Does each page have different, useful information, not just a swapped city or product name?
2. Do users actually search for this page?
3. If this page were deleted, would anyone lose out?

If the answer is no, do not build it.

## Quality control
- Start from a small sample. Measure indexing and clicks before adding more.
- Set a minimum threshold for pages allowed to be published (unique content, real data).
- Human review of a random sample.
- Prepare a pruning mechanism: pages that are not indexed or get no impressions after a reasonable period are consolidated or removed.

## Prune the inventory
Large sites often benefit from pruning thin pages. Consolidate into stronger pages and 301 to a relevant target, rather than mass deleting without a map.

## Sitemaps at scale
A single sitemap file is limited to 50 MB uncompressed or 50,000 URLs. Use a sitemap index and split by content type so it is easy to monitor in GSC.

## Exercise
Design one programmatic project with a real data source. Write three feasibility tests and the minimum page threshold.

## Comprehension check
- What is the difference between healthy programmatic SEO and scaled content abuse?
- How does a pruning mechanism work?
